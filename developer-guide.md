# Developer Guide & Contribution Workflow

This document outlines local environment setup, compendium management rules, and best practices for developing inside the **Eskie Macro Pack** module.

---

## 1. Module Overview & Project Architecture

Eskie Macro Pack maintains two dynamic Foundry VTT compendiums:

- **`eskie-aa-integration`** (`packs/eskie-aa-integration/`): Compendium containing Automated Animation (AA) integration macro entries.
- **`eskie-standalone-macros`** (`packs/eskie-standalone-macros/`): Compendium containing individual standalone macros from `src/standalone-macros/`.

### Source Files vs. Packed Databases

- Human-readable source macros live in `src/standalone-macros/*.js`.
- Whenever a macro is added or edited in source files, dev environment maintainers can click **Generate Compendiums** under *Module Settings* (or call `updateMacroCompendiums()`) to update the dynamic compendium database.

---

## 2. Compendium LevelDB Database Hygiene

Foundry VTT uses LevelDB to store compendium records. When running Foundry locally, several internal database files are accessed or generated:

| File / Pattern | Description | Tracked in Git? |
| :--- | :--- | :--- |
| **`*.ldb`** | **Table Data.** Immutable LevelDB data tables containing the actual macro payloads. | **Yes** (when entries change) |
| **`CURRENT`** | Single-line text pointer to the active `MANIFEST-XXXXXX` number. | **Yes** (must match `MANIFEST`) |
| **`MANIFEST-XXXXXX`** | Master sequence registry of valid `.ldb` data segments. | **Yes** (replaces old manifest) |
| `*.log` | Active Write-Ahead Log (WAL) buffer before flush to `.ldb`. | Only when active mutations exist |
| `LOG` / `LOG.old` | ASCII diagnostic output generated by the C++ LevelDB engine. | **No** (ignored by `.gitignore`) |
| `LOCK` | Process handle lock preventing simultaneous DB access. | **No** (never commit this) |

## 3. Pre-Commit Hook: Automatic DB Churn Cleanup

Opening and closing Foundry VTT can generate noisy background compaction logs or sequence handle changes in `packs/` even when zero compendium entries were modified.

To keep git history clean, the repo includes an embedded Git pre-commit script at `.githooks/pre-commit`.

### One-Time Local Setup

After cloning this repository (or checking out a new dev environment), activate the project hooks directory by running:

```bash
git config core.hooksPath .githooks
```

### How the Pre-Commit Rule Works

Every time you execute `git commit`:
1. The hook checks if any `*.ldb` data files were created, modified, or staged in `packs/`.
2. **If `*.ldb` files changed**: Your real compendium updates are kept and committed normally.
3. **If NO `*.ldb` files changed**: The hook automatically discards runtime noise (`CURRENT`, `MANIFEST`, and `.log` churn) in `packs/` before completing the commit.

## 4. Workflow: Adding a New Standalone Macro

Follow these steps when adding a new macro to the pack:

1. Create your new macro file in `src/standalone-macros/your-macro-name.js`.
2. Register the filename alphabetically inside `KNOWN_STANDALONE_MACROS` in `src/lib/standalone-macros.js`.
3. Launch Foundry VTT, go to **Game Settings → Module Settings → Eskie Macro Pack**, and click **Generate Compendiums**.
4. Stop your Foundry VTT server cleanly so memory writes flush into disk.
5. Inspect changes using `git status`:
   - You should see modified source files and new/modified `.ldb`, `MANIFEST-*`, and `CURRENT` files under `packs/eskie-standalone-macros/`.
6. Stage and commit your changes:
   ```bash
   git add src/ packs/
   git commit -m "feat(macro): add your-macro-name standalone macro and update compendium"
   git push origin next
   ```
